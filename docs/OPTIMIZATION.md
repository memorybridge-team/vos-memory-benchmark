# 평가 실행 경량화

이 문서의 최적화는 평가 정의 버전 4에서 검증했고 실행 구현 버전(`runtime_revision`)은 2다.
아래 수치는 이전 실행 버전 2의 기록이다. 현재 평가 정의는 6, 실행 버전은 5이며 SQLite 저장과 측정 없는 구간의 CPU 프리페치를 추가했다. 평가 정의 버전 5 이하 JSONL은 현재 재개에서 읽지 않는다.
프레임별 J·F·J&F, 회복률 원점수, 기억 프레임별 R² 충분통계량은 계속 보존한다.

## 현재 실행 버전 5

RGB 입력·Native R² 기준의 제한된 CPU 캐시, benchmark 전용 가시성 조회 생략 및 결과별 트랜잭션을 유지하는 SQLite 연결 재사용을 추가했다. 설정·측정 제외 범위와 검증 결과는 [EXTRA_OPTIMIZATION.md](EXTRA_OPTIMIZATION.md)에 있다. 정밀도·입력 해상도·GPU 추론 순서·집계 정의는 바꾸지 않는다. 이전 시간 숫자와 동등하다고 가정하지 않는다.

## 이전 실행 버전 4

- 측정 없는 구간에서 CPU 채점 worker 1개와 GPU 추론을 겹친다. 실행/대기 마스크는 4장으로 제한하고, 큐에 복사하여 추론 마스크 재사용의 영향을 막는다.
- 정답 PNG 및 정답 경계/거리 변환은 객체별 128 MiB LRU에 보관한다. 긴 영상의 순차 재접근에서는 캐시 적중률이 낮을 수 있으므로 CPU 프로파일의 적중/누락 수로 판단한다.
- 전환 준비·replay 측정 동안 채점 worker가 없고, 추적 종료에서 채점과 프리페치를 모두 끝낸다. 저장 전에 오류를 전파하며 부분 채점을 저장하지 않는다.
- DB 원점수 메타데이터에 추적 단위 CPU 프로파일을 저장한다. `tracking_id`로 여러 전환의 중복을 제거한다. 이미지 준비·GT 준비·채점·대기시간은 겹칠 수 있으므로 실행시간으로 더하지 않는다.
- 실행 버전 4와 worker/큐/캐시 설정이 실험 ID에 포함된다. 실행 버전 3 결과는 그대로 보존하며 ID를 선택해 재집계한다. 서버 GPU 속도 개선은 아직 측정하지 않았다.

엄밀한 점수·기억·회차·저장 검증과 적용 전 제한은 [CPU_RELIABILITY_AUDIT.md](CPU_RELIABILITY_AUDIT.md)에 기록했다. 실제 Small/Base+ CPU 비교와 테스트는 통과했지만 CUDA 추론 동등성은 미검증이다. 측정 경계를 보존했다는 사실이 변경 전후 전환 시간 숫자의 동등성을 뜻하지는 않는다.

CPU 채점만 측정한 합성 사례에서는 720×480 정답 24장을 4번 채점했다. macOS arm64, OpenCV 4.14.0(내부 스레드 8개), 정답 배열이 이미 RAM에 있는 조건이다. 5회 측정 중앙값은 기존 J/F 0.250초, 정답 캐시 사용 0.161초로 채점 시간은 35.4% 줄었다. 96개 점수 쌍은 정확히 일치했다. 첫 캐시 준비 비용도 포함했으며 이미지 I/O·SAM2·GPU·비동기 겹침은 측정하지 않았다. 이 수치를 전체 평가의 속도 개선으로 사용하지 않는다. 로컬 기록은 `outputs/validation/cpu_scoring_profile.json`이다.

- 25/50/75% 전환마다 s-start<8이면 모델 로딩 전에 제외한다.
- SQLite 완료 키만 조회하고 원점수/자식 행은 결과 단위로 원자적으로 저장한다. 집계는 가시 GT 프레임만 읽는다.
- CPU worker 한 개가 다음 한 프레임을 준비한다. Small과 Base+의 측정 없는 미래 구간에만 적용하고, 측정 프레임을 미리 읽지 않는다. GPU 추론은 순차 실행한다.
- 측정하지 않은 프레임 시간은 NULL이다. CUDA 동기화와 전환 비용 범위는 그대로 유지한다.
- 실제 SAM2 2.1 Small·Base+ 체크포인트에서 CPU 프리페치 켬/끔 마스크를 비교했다. DAVIS motocross-jump의 0~7프레임이 각각 8/8 일치했고 최대 픽셀 차이는 0이었다. CPU 설치의 CUDA 확장 부재로 hole-fill 후처리는 생략되었다. 검사 기록은 `outputs/validation/sqlite_prefetch_sam2_cpu.json`이다.
- 실제 GPU 활용률과 전체 실행 시간 개선은 아직 측정하지 않았다. 설치 SAM2 preflight를 다시 통과한 뒤 서버에서 확인한다.

## 이전 실행 버전 2의 변경 사항

- CPU↔GPU 기억 이동은 `to(copy=True)` 한 번으로 독립된 tensor를 만든다. 이동 후 전체 `clone()`을 다시 하지 않는다. 같은 장치에서 복사할 때도 원본과 저장 공간을 공유하지 않는다.
- GPU 시간 동기화 및 최고 메모리 조회는 준비·replay까지만 수행한다. Native는 75% 전환까지 측정한다. 이후 모든 프레임의 추론/채점은 계속한다. replay가 없는 방법도 준비 시간·전환 최고 메모리는 기록한다.
- 재개 시 미완료한 **방법×전환 시점**만 처리한다. Source-only 결과가 필요할 때는 Small을 끝까지 처리하고, 다른 방법만 남았으면 마지막 필요한 전환까지만 처리한다.
- Small 기억은 Direct State Copy/translator가 필요한 전환에서만 꺼낸다. anchor/replay용 최초 프롬프트·마지막 비어 있지 않은 마스크는 그대로 유지한다.
- 각 GPU는 자신의 미완료 영상 파일 목록과 요청 seed/회차의 Native 기준만 보관한다. 완료된 실행과 빈 shard는 모델을 로딩하지 않는다. 남은 조건에 필요한 모델만 로딩한다.
- 완료 키와 Native JSONL은 한 줄씩 읽는다. 표 집계도 현재 버전·선택 seed/회차에 맞는 중복 없는 결과만 보관한다. 집계 자체에는 선택한 원본 프레임 데이터의 RAM이 여전히 필요하다.
- Native 점수 사전은 객체당 한 번 만들어 방법들에서 재사용한다. translator 가중치 SHA256도 작은 청크로 읽어 검사한다.
- 준비/추적/채점에서 예외가 나면 세션을 닫아 GPU 상태를 해제한다.

## 검증 결과

가짜 모델·30프레임 영상의 객체 한 개에서 최적화 전 코드와 6개 방법×50/75%의 점수가 동일했다. translator 75%만 재개한 점수 및 R² 원점수도 동일했다. 시간/GPU 비용 및 실행 메타데이터는 이 점수 동등성 비교에서 제외했다.

| 확인 대상 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 전체 평가의 `cost.now()` 호출 수 | 295 | 96 |
| translator 75%만 재개의 추론 프레임 수 | 52 | 30 |
| 같은 재개의 Small 기억 export 수 | 2 | 1 |
| JSONL 완료 키 읽기의 Python 할당 최고치 | 21.818 MiB | 0.851 MiB |

JSONL 측정은 60줄×1,200개 합성 프레임 값, 파일 약 5.217 MiB에서 `tracemalloc`으로 수행했다. 이 값은 Python 할당량이며 프로세스 전체 RAM이나 GPU VRAM 측정값이 아니다. 호출 수 감소도 실제 GPU 실행 시간의 감소율을 뜻하지 않는다. 상세 측정은 `outputs/validation/optimization_report.json`에 있다.

기존 지표·회복률·R²·그래프·전체 평가 테스트와 `tests/test_optimizations.py`로 복사 독립성, 측정 범위, 재개 동등성, 두 shard의 누락/중복 및 완료 실행의 로딩 생략을 확인한다. 실제 SAM2 GPU 속도와 VRAM 절감량은 서버에서 확인해야 한다.

## 실행 및 비용 비교

기존 명령 그대로 사용한다. 여러 GPU에서는 GPU마다 `CUDA_VISIBLE_DEVICES`와 `--shard i/n`을 지정한다. 영상 단위로 분할하며 같은 객체를 두 프로세스에 동시에 배정하지 않는다.

집계는 DB의 실험 ID를 선택한다. `--list-experiments`로 목록을 보고 `--experiment-id ID`로 지정한다. 실험이 하나면 자동 선택하며 여러 개거나 선택한 결과가 없으면 오류로 종료한다. DB에 저장된 평가 설정·방법 revision을 사용하므로 체크포인트와 데이터가 없는 컴퓨터에서도 표를 만든다. 이 변경은 추론·재개 검사를 바꾸지 않는다.

현재 재개는 experiment_id·방법 revision이 같은 DB 점수·Native 기준만 사용한다. 원점수의 `runtime_revision`은 이번 실행 구현이고, `cost_runtime_revision`은 해당 비용을 실제 측정한 구현 버전이다. Native 비용은 기준 파일의 버전을 따른다. 최적화 이전 기준 파일에 버전 표시가 없으면 1로 기록한다. Source-only의 비용 버전은 null이다.

기존 실행 결과를 이어하면 최적화 전후 시간·메모리 값이 섞일 수 있다. 비용 비교를 위한 본실험은 새 `OUTPUT_ROOT`에 영상 목록을 만든 뒤 같은 코드·같은 GPU 조건으로 전체 실행한다. 모델 가중치·정밀도·메모리 유지 길이·3회 반복 및 지표 공식은 이번 변경으로 바뀌지 않았다.
