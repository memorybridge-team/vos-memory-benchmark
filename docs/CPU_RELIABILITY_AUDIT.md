# CPU 채점 최적화 신뢰도 검증

이 문서는 실행 버전 4의 검증 기록이다. 이후 적용한 실행 버전 5의 추가 최적화는 [EXTRA_OPTIMIZATION.md](EXTRA_OPTIMIZATION.md)에 별도로 기록한다.

2026-10-10, `feat/switch25-sqlite`의 미커밋 변경을 검증했다. 변경 전 실제 실행 비교 기준은 `b05a6371fe95059343ce93c6eedaa147cc0b0209`다. 적용된 변경은 CPU 비동기 채점, 정답 LRU와 CPU 프로파일 기록이다. 추가 제안인 공유 RGB 캐시, Native R² 기준 캐시, 가시성 조회 생략, SQLite 연결 재사용은 적용하지 않았다.

## 판정

검증한 입력과 실행 환경에서는 정확도·원점수·집계 표본 변경이 발견되지 않았다. CUDA에서의 추론 동등성과 측정 시간의 동등성까지 확인한 것은 아니다. 코드 구조, 가짜 모델 테스트, 실제 체크포인트 CPU 실험을 구분한다.

| 확인 대상 | 검증과 결과 | 범위 |
| --- | --- | --- |

`tests/test_*.py` 11개를 각각 독립 프로세스에서 실행해 모두 통과했다. 새 회차 검증은 `tests/test_cpu_reliability.py`에 있다. `git diff --check`도 통과했다.

실제 체크포인트 검사는 CPU Torch 2.13.0에서 수행했다. 진단 fixture로 `scripts/0_check_sam2.py`의 실제 검사 함수를 호출했고, 기억 형태·dtype·pos_enc·Small/Base+ roundtrip이 통과했다. cut=18, 이후 1프레임 조건이며 별도 출력 폴더를 사용했다. 서버의 본평가 preflight를 대신하지 않는다. CUDA 확장이 없어 설치 SAM2의 CPU fallback에서는 hole-fill 후처리를 생략했다.

## 정확도 보존 근거

worker에는 프레임 번호와 독립적으로 복사한 CPU 예측 마스크만 넘긴다. GPU, SAM2 상태, 전환 준비, SQLite에 접근하지 않는다. 정답 캐시는 객체 실행마다 새로 생성되며 mask·ignore·boundary·distance 배열은 읽기 전용이다. 결과는 제출한 프레임 순서로 회수하고 추적 종료 때 전부 완료한 뒤 저장한다. 추론은 기존 순서로 진행한다.

원점수에서는 정답 없는 프레임의 NULL, 안 보이는 객체, 예측 실패 0점이 유지된다. 현재 표의 가시 GT 필터와 Native 프레임별 중앙값 정의도 유지된다. 이 검증은 그 통계 정의 자체의 연구 타당성을 확정하는 검증이 아니다.

입력 파일과 채점 설정은 실행 중 고정되어야 한다. 파일이나 `BOUNDARY_THRESHOLD`를 캐시가 살아 있는 동안 변경하는 사용법은 검증 범위가 아니다.

## 추가 제안에 대한 제한

| 제안 | 현재 확인한 내용 | 적용 전 필요한 조건 |
| --- | --- | --- |
| 공유 RGB 캐시 | 별도 CPU prototype에서 두 실제 모델의 마스크·기억·점수 일치 | 파일/전처리 설정을 완전히 구분한 키, 저장 공간 독립성, 캐시 상한, 측정 구간 우회 및 CUDA 비교 |
| Native R² 기준 캐시 | 현재 식은 CPU float64의 중심화된 SST를 사용 | 실제 Native tensor 기준으로 캐시하고 계산 순서·dtype·누락/비유한/분산 0 상태를 유지. `sum(x²)-n*mean²`로 바꾸면 수치 상쇄 위험 |
| 가시성 scalar 조회 생략 | benchmark는 `FrameOut.visible`을 읽지 않음. 별도 prototype에서 마스크·기억·점수 일치 | 일반 Session의 가시성 반환 의미를 보존하거나 명시적 benchmark 옵션 필요. SAM2 내부 presence logits는 유지 |
| SQLite 연결 재사용 | 현재 코드의 트랜잭션·재개 테스트는 통과 | 재사용 구현의 결과별 commit/rollback, FK, 재시도 및 장애 주입 검증 필요. 중첩 connection context의 조기 commit 위험 확인 |

prototype 결과를 미구현 제안 전체의 안전성 증명으로 사용하지 않는다. 기존 서버 `157.157.221.29:38344`는 현재 SSH 연결이 거절되어 CUDA/BF16 추론 비교는 수행하지 못했다.

## 시간 지표

타이머 경계와 CUDA 동기화 정의는 유지했다. 측정 구간에서 직접 실행하는 채점 worker도 없다. 그러나 캐시 적중, CPU 자원 경쟁 이력, GPU 클록·온도는 다음 측정에 영향을 줄 수 있다. 따라서 변경 전후 전환 시간의 동일성을 보장하지 않는다.

현재 `runtime_revision=4`와 worker/큐/캐시 설정은 실험 ID에 포함된다. 속도 비교는 같은 GPU·설정·환경에서 코드 버전을 구분하여 다시 측정해야 한다. CPU 점수 일치를 전체 GPU 속도 향상이나 GPU 측정 신뢰성의 증거로 사용하지 않는다.

## 로컬 증거
